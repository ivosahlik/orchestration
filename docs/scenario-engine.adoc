== Overview

The **UBot Scenario Engine** is a Spring Boot 4 service that accepts scenario execution requests (via REST or Kafka), queues them in MongoDB, and dispatches them onto Java virtual threads.
Cron-based batch jobs are managed through `ScheduledJob` documents and evaluated on every scheduler tick.

=== Key design decisions

[cols="1,2", options="header"]
|===
| Decision | Rationale
| *MongoDB as source of truth* | No in-memory queue; crash-safe by default. PROCESSING scenarios are recovered to WAITING on restart.
| *Virtual threads (Java 25)* | One thread per running scenario – cheap, non-blocking, no thread-pool sizing required.
| *No Quartz / no JPA* | Spring `@Scheduled` tick evaluates cron expressions from MongoDB documents.
| *Two-tier concurrency guard* | Global cap (`max-total`) + per-process cap (`per-process[code].max`) via paired semaphores.
| *Template method pattern* | `AbstractScenario.execute()` owns lifecycle; subclasses implement only `doExecute()`.
|===

title Scheduled Job – URL Consumer Execution Flow

participant "Spring\n@Scheduled"     as sched    order 1
participant "SchedulingService"       as schedSvc order 2
participant "MongoDB\n(scheduled_jobs)" as jobDb  order 3
participant "WorkingHoursService"     as wh       order 4
participant "External URL"            as url      order 5
participant "ScenarioExecutionService" as execSvc order 6
participant "MongoDB\n(executions)"   as execDb   order 7
participant "ConcurrencyGuard"        as guard    order 8
participant "AbstractScenario"        as scenario order 9
participant "StepProcessor"           as steps    order 10

== Tick ==

sched    -> schedSvc  : tick()
schedSvc -> jobDb     : findByEnabled(true)
jobDb   --> schedSvc  : List<ScheduledJob>

loop for each enabled job
  schedSvc -> schedSvc : CronExpression.parse()\nnextAfterLast ≤ now ?

  alt cron not yet due
    schedSvc -> schedSvc : skip
  else cron fired
    schedSvc -> wh        : isWithinWorkingHours(rule)
    wh       --> schedSvc : true / false

    alt outside working hours
      schedSvc -> schedSvc : log + skip
    else within working hours

      == Fetch Input Data ==

      alt urlConsumer is set
        schedSvc -> url      : GET urlConsumer
        url      --> schedSvc : response body (String inputData)
      else inputDataTemplate
        schedSvc -> schedSvc : replace {{now}} → inputData
      end

      == Submit Execution ==

      schedSvc -> execSvc   : submit(correlationId, scenarioCode,\nthreadCode, inputData, steps, …)
      execSvc  -> execDb    : save(state=WAITING)
      execDb  --> execSvc   : saved ScenarioExecution
      execSvc --> schedSvc  : ScenarioExecution

      schedSvc -> jobDb     : save(job.lastTriggered = now)
    end
  end
end

== Dispatch Loop (runs every ~1 s) ==

execSvc  -> execDb   : findByState(WAITING)
execDb  --> execSvc  : List<ScenarioExecution>

loop for each WAITING execution
  execSvc -> guard   : tryAcquire(threadCode)

  alt no semaphore slot
    guard --> execSvc : empty
  else slot acquired
    guard --> execSvc : Permit

    execSvc -> execDb  : save(state=PROCESSING, runStart=now)

    == Virtual Thread: executeScenario ==

    execSvc -> scenario : new (prototype bean)
    execSvc -> steps    : runSteps(PRE_PROCESSING)
    execSvc -> scenario : setInputData(inputData)

    loop execute items
      execSvc -> steps    : runSteps(PRE_ITEM)
      execSvc -> scenario : execute()
      note right : doExecute() contains\nbusiness logic
      scenario --> execSvc : hasMore (boolean)
      execSvc -> steps    : runSteps(POST_ITEM)

      alt no more items
        execSvc -> steps    : runSteps(POST_PROCESSING)
        execSvc -> execDb   : save(state=COMPLETED, runEnd=now)
        execSvc -> guard    : permit.close()
      else suspend signal received
        execSvc -> execDb   : save(state=SUSPENDED, context)
        execSvc -> guard    : permit.close()
      end
    end
  end
end

@enduml

== Submit ==

client  -> ctrl    : POST /api/scenarios\n{ scenarioCode, inputData, … }
ctrl    -> execSvc : submit(correlationId, …)
execSvc -> db      : save(state=WAITING)
db     --> execSvc : ScenarioExecution
execSvc --> ctrl   : ScenarioExecution
ctrl   --> client  : 202 Accepted\n{ correlationId }

== Poll status (optional) ==

client  -> ctrl    : GET /api/scenarios/{correlationId}
ctrl    -> execSvc : getStatus(correlationId)
execSvc -> db      : findById
db     --> execSvc : ScenarioExecution
execSvc --> ctrl   : ScenarioExecution
ctrl   --> client  : 200 OK { state, statistics }

== Dispatcher picks it up ==

execSvc -> db      : findByState(WAITING)
db     --> execSvc : [execution]
execSvc -> guard   : tryAcquire(threadCode)
guard  --> execSvc : Permit
execSvc -> db      : save(state=PROCESSING)
execSvc -> scenario : setInputData() + execute()
scenario --> execSvc : done (false)
execSvc -> db      : save(state=COMPLETED)
execSvc -> guard   : permit.close()

== Final poll ==

client  -> ctrl    : GET /api/scenarios/{correlationId}
ctrl   --> client  : 200 OK { state=COMPLETED, result=OK, statistics }

== Optional: Send signal ==

client  -> ctrl    : POST /api/scenarios/{correlationId}/signal\n{ signal: "TERMINATE" }
ctrl    -> execSvc : signal(correlationId, "TERMINATE")
note right of execSvc : Routes to running\nScenario.processSignal()
execSvc --> ctrl   : true
ctrl   --> client  : 200 OK

@enduml

== Running ==

execSvc -> scenario : execute() [item N]
scenario --> execSvc : hasMore = true

client  -> ctrl    : POST /api/scenarios/{id}/suspend
ctrl    -> execSvc : suspend(correlationId)
execSvc -> execSvc : shouldSuspend.set(true)
execSvc --> ctrl   : true
ctrl   --> client  : 200 OK

execSvc -> execSvc  : shouldSuspend == true → break loop

execSvc -> execSvc : permit.close()

client  -> ctrl    : POST /api/scenarios/{id}/unsuspend
ctrl    -> execSvc : unsuspend(correlationId)
execSvc -> db      : save(state=WAITING)
execSvc --> ctrl   : 200 OK
ctrl   --> client  : 200 OK

note over execSvc : Dispatcher picks up\nWAITING execution again

execSvc -> scenario : setContext(saved context)
execSvc -> scenario : execute() [item N+2]

consumer -> consumer  : objectMapper.readValue(payload,\nOffertoolOfferEvent.class)
note right of consumer
  Parses: offerId, variantId,
  variantState, testAppLogin,
  platform, type, contractDuration,
  clientCommitment …

consumer -> consumer  : correlationId = UUID.randomUUID()

db      --> execSvc   : ScenarioExecution
execSvc --> consumer  : ScenarioExecution
note right of kafka   : Kafka offset committed —\nno message loss

== Dispatch Loop (≈every 1 s) ==

execSvc  -> db        : findByState(WAITING)
db      --> execSvc   : [ScenarioExecution]

execSvc  -> guard     : tryAcquire("DEFAULT")

alt no semaphore slot available
  guard --> execSvc   : empty — will retry next tick
else slot acquired
  guard --> execSvc   : Permit

  execSvc -> db       : save(state=PROCESSING, runStart=now)

  == Virtual Thread: executeScenario ==

  execSvc -> registry  : getScenario("OFFERTOOL_BATCH_PROCESS")
  registry --> execSvc : OffertoolScenario (new prototype)

  execSvc -> steps     : runSteps(PRE_PROCESSING)

  execSvc -> scenario  : setInputData(payload)
  note right of scenario
    Parses JSON → OffertoolOfferEvent;
    logs offerId, variantId, ca,
    contractId, variantState
  end note

  == Single-shot Execution ==

  execSvc -> steps     : runSteps(PRE_ITEM)
  execSvc -> scenario  : execute()

  scenario -> scenario : setScenarioStep("processing-offer")
  scenario -> scenario : log platform, type, contractDuration
  note right of scenario : TODO: business logic\n(CRM call, bot action, …)
  scenario -> scenario : setResultOK(\n  "Offer processed: offerId=X variantId=Y")
  scenario -> scenario : increaseSuccess()
  scenario --> execSvc : hasMore = false\n(single-shot returns false)

  execSvc -> steps     : runSteps(POST_ITEM)
  execSvc -> steps     : runSteps(POST_PROCESSING)

  execSvc -> db        : save(state=COMPLETED,\nrunEnd=now, statistics)
  execSvc -> guard     : permit.close()
end

  ScenarioExecution.statistics includes:
  offerId, variantId, platform,
  type, variantState  (extendStatistics)
end note

== Component Summary

[cols="1,2,2", options="header"]
|===
| Component | Responsibility | Key methods

| `ScenarioController`
| REST entry point for scenario lifecycle
| `submit()`, `status()`, `signal()`, `suspend()`, `unsuspend()`

| `SchedulingController`
| CRUD for `ScheduledJob` documents
| `create()`, `update()`, `delete()`, `listAll()`

| `SchedulingService`
| Evaluates cron jobs every 100 ms; fetches URL or resolves template; calls `submit()`
| `tick()`, `evaluate()`, `fetchFromUrl()`, `resolveInputData()`

| `WorkingHoursService`
| Parses `MON-FRI(08:00-17:00)\|SAT(09:00-12:00)` rules; OR semantics
| `isWithinWorkingHours(rule, now)`

| `ScenarioExecutionService`
| Dispatch loop; virtual-thread lifecycle; suspend/resume
| `submit()`, `signal()`, `suspend()`, `unsuspend()`, `dispatchLoop()`

| `ConcurrencyGuard`
| Two-tier semaphore (global + per-process)
| `tryAcquire(threadCode)` → `Permit`

| `AbstractScenario`
| Template-method base for all scenarios; counters; signal handling
| `execute()`, `doExecute()`, `increaseSuccess()`, `isTerminateSignal()`

| `StepProcessor`
| PRE/POST hook extension point
| `execute(type, execution, scenario, code, params)`
|===

== Configuration Reference

[source,yaml]
----
engine:
  concurrency:
    max-total: 50           # Global ceiling for all concurrent scenarios
    per-process:
      DEFAULT:
        max: 10             # Max concurrent DEFAULT-bucket scenarios
        min: 2              # Min guaranteed slots
      REPORT:
        max: 5
        min: 1
  executor:
    check-interval-ms: 1000 # Dispatcher poll interval
    recover-on-start: true  # Move PROCESSING → WAITING on startup

spring:
  kafka:
    bootstrap-servers: localhost:9092
    consumer:
      group-id: ubot-scenario-engine
  data:
    mongodb:
      auto-index-creation: true
  mongodb:
    uri: mongodb://ubot_admin:ubot_password@localhost:27017/ubot-scenario-engine?authSource=admin
  threads:
    virtual:
      enabled: true         # Virtual threads for Tomcat + @Async + @Scheduled
----
